# xv6 源码问题集

本目录用于以问题驱动的方式学习当前仓库源码。问题不要求复述函数用途，而是要求追踪控制流、状态转换、锁、资源所有权和失败路径。

## 如何根据代码生成问题

问题必须从当前仓库的代码中产生，而不是先准备一组固定问题，再到代码中寻找答案。生成时采用以下过程：

1. 选择一段待学习的代码范围，阅读它的定义、调用者、被调用者、相关数据结构、汇编代码和构建配置；暂时不要预设问题。
2. 还原代码实际执行的控制流和数据流，记录对象状态、资源所有权、锁、中断、页表、栈和特权级在各个边界上的变化。
3. 找出仅看单个函数无法解释的代码点，例如隐含前提、特殊执行顺序、跨函数不变量、并发可见性、失败分支、资源上限和清理责任。
4. 将这些代码点改写为需要追踪源码才能回答的问题。问题应要求解释“代码怎样到达这里”“为什么需要这个条件”或“条件被破坏后会出现什么可观察结果”，但不在题目中预先给出结论。
5. 用当前源码反向校验每个问题：题目的前提必须真实存在，答案必须能引用明确的执行路径和状态变化，并且最好能通过断点、日志、测试或故障注入验证。
6. 删除只需复述函数用途、只考查通用教材概念或依赖仓库外假设的问题；完成生成后，再按涉及的代码范围分类并编号。

源码发生变化时，应重新执行上述过程，检查原问题的前提是否仍然成立，并从新增或改变的实现中继续生成问题。因此，本目录的问题集是当前代码的学习索引，而不是脱离代码长期不变的题库。

本仓库暂时存放了通用的 [`generate-code-questions`](../../.agents/skills/generate-code-questions/SKILL.md) skill。该 skill 不依赖 xv6 或本目录结构；在本项目中使用时，通过 `$generate-code-questions` 指定待分析的源码范围，并明确将结果写入 `docs/questions/`。

## 回答标准

回答每个问题时至少给出以下内容：

1. 从入口到结果的完整调用链。
2. 关键对象在每一步之前和之后的状态。
3. 当前特权级、页表、栈、锁和中断状态。
4. 资源由谁拥有、何时转移、失败时由谁释放。
5. 一个可以观察结论的 GDB 断点、日志或定向测试。

只说明“某函数完成某功能”不算回答。涉及并发时，应说明其他 hart 可以在哪些锁外边界观察状态；涉及失败时，应区分完整回滚、部分副作用、睡眠、kill 和 panic。

## 建议顺序

先完成启动与陷阱，再依次学习进程与调度、虚拟内存、文件系统与存储，最后集中处理同步与失败问题。首次阅读可以只追主调用链，第二遍再补锁顺序、资源所有权和异常分支。

本仓库与常见 xv6 教材版本存在差异，答题前应先阅读[仓库差异台账](../xv6-riscv/architecture/repository-delta.md)。当前源码是最终依据。
