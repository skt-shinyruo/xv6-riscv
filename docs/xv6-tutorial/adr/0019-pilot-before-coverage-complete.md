# Verify a Thin Pilot Before Expanding Coverage

Implementation will first establish the standalone directory, manifest, validator, generated navigation, and unit templates, then verify the foundation path and gate. The first core pilot will run and observe xv6, explain user programs and the ABI, trace one system-call round trip, complete a minimal system-call bounded change lab, and migrate only the corresponding source questions before the remaining macro-stages and evidence domains expand.

## Considered Options

- Write all tutorial prose before building validation and experiment support.
- Begin with the complete `fork -> exec -> wait` flow or an advanced COW project.
- Migrate the complete existing question set before its tutorial prerequisites exist.

## Consequences

A unit or path is `verified` only after technical release checks and a recorded walkthrough by a non-author matching its entry contract. Incremental verified releases use `0.x`; `1.0.0` is reserved for a pinned baseline that is coverage-complete and passes the complete release gate.
