# Distribute Practice and Require Three Evidence Domains

Every core learning unit will include an observation exercise, and every macro-stage will include at least one bounded change lab. Core completion requires evidence projects in concurrency and waiting, memory and resource ownership, and persistence and recovery; automation checks executable facts while explicit rubrics assess models, invariants, state transitions, and evidence limits.

## Considered Options

- Concentrate all implementation work at the end of the curriculum.
- Require only one unrestricted evidence project.
- Make every advanced project mandatory at the same level.
- Accept only automatically graded outcomes.

## Consequences

The standalone tutorial will independently redesign syscall and lazy-NX topics as bounded change labs, COW as a memory and ownership project, lost wakeup and parallel buffer cache as concurrency options or a progression, and offline fsck as a persistence project. Foundation, observation, and bounded tasks receive layered hints and separate answer pages; evidence projects receive rubrics, report structures, and partial oracle guidance rather than authoritative complete patches.
